# DroidVM 1.0.1 (10001)

基于上游 [Droid-VM/DroidVM](https://github.com/Droid-VM/DroidVM) 的公开 fork 版本。

## 主要变更

- **首页运行环境卡**：ROOT、虚拟化状态、大页池实时容量（可用 / 目标），以及「释放大页 / 获取大页」按钮。移除了普通内存行和旧的「释放内存」按钮；在这台机器上决定 VM 能否启动的是大页池，不是 `MemAvailable`。
- **修复 VM 列表重复项**：自动识别此前只检查每个 VM 的启动镜像；已挂到现有 VM 的第二块盘会被当成新磁盘，自动建成一个 512 MB 的 `(N)` 副本，删掉后下次刷新又会出现。现在检查全部磁盘路径。
- **另一个独立加固（不是重复项的根因）**：磁盘负载未落盘的 VM 包不再注册残缺 VM；启动时清理旧的 512 MB 重复残留。
- **Windows 11 验证**：zlib 压缩的 `26h2.qcow2`（39.05 GiB → 8.31 GiB）可启动到桌面；GXDE ISO 与 Windows 盘同时挂载时，固件优先启动 ISO 的 GRUB。
- **更新检查**：改为读取本仓库的 GitHub Releases；设置页新增本地更新日志。
- **开源信息**：新增 `FORK.md`、`TODO.md` 和面向用户的更新日志，隐私协议升级到 v2。
- **构建**：`libvncserver` 内置并带 16 KB 页对齐；构建目录和签名可用环境变量覆盖。

## 安装

- 要求 arm64 设备，以及 Gunyah / GenieZone / KVM 之一的虚拟化节点。
- 本 APK 使用 **debug keystore** 签名，与上游正式版签名不同。若设备上已安装上游版本，需先卸载（`/sdcard/DroidVM` 下的磁盘镜像不会被卸载删除，但仍建议先备份）。
- 安装后首次启动请授予通知/存储权限；VM 启动依赖 root 时，请确保 KernelSU / Magisk 已授权。

## 已知限制

- Windows 3D 仍不可用：稳定配置为关闭 `gpu-0`，使用 `simplefb` + VNC 5909。
- Gunyah 的 `MEM_ACCEPT 0x15` 在多次启动后可能出现，完整重启可清 RM 状态（软重启不行）。
- 大页池不足时 2 GB VM 可能启动失败；先点「获取大页」或使用 `gh-hugepage-reserve` 模块的 `boot_acquire`。
- 启动顺序仍由 UEFI 固件的 Boot Manager 决定，编辑器不提供启动顺序。
